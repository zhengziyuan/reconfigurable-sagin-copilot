# v0.8 产品审视与模型审计

审视日期：2026-10-05。本文描述代码已实现的范围，不将目录、按钮、适配器或接口预留计为生产集成。

## 审视结论

产品已经具备地理场景、资产、性能场、部署/资源计算和报告的基本闭环。前一版本的问题不只是页面数量，而是编辑、真实数据、模型一致性和可部署性之间的断点。

本轮修复：硬编码 API 导致容器前端访问使用者本机；启动重复优化；参数面板与求解器脱节；资源算法绕开 L1；场景版本与运行绑定不完整；雨衰系数插值；星地局部平面几何；相对色阶影响跨运行比较；部分离线占位值表现成证据。

这些修复提升原型可信度，不把原型自动升级成商用产品。

## 物理建模

### ITU-R P.838-3

`standards/rain_p838.py` 按官方公式 1-5、表 1-4 实现水平/垂直极化频率拟合与仰角/极化合成，取代粗插值。自动测试使用表 5 的 1、10、28、100 GHz 检验系数。

只验证 `k`、`alpha` 和比衰减层，不等于实现 P.618 超越概率、P.837 地理雨率或 P.839 雨高。有效雨程、气体、云雾、闪烁仍含近似。

来源：[ITU-R P.838-3](https://www.itu.int/rec/R-REC-P.838-3-200503-I)。

### 星地几何

`geo.satellite_geometry` 使用球形地球 ECEF 计算斜距和接收仰角；低于默认 10 度遮罩的卫星不服务。测试覆盖 600 km 天顶星、地球背面不可见星与保真回退。

尚未采用 WGS84 椭球、SGP4/TLE 时序、天线方向图、Doppler/时延时变或地形遮挡。地图卫星点是瞬时星下投影，不是轨道展示。

### 统一链路与 L2

资源分配使用与覆盖仿真相同的 L0/L1 链路预算及所选 RIS/MIS 帮助节点。但性能场容量与资源调度容量仍采用不同资源抽象，不应混同为同一业务吞吐。回传仍是估计，未实现多跳流守恒与队列。

L2 适配器未连接 RT 时返回实际 `fidelity_level=1`，不把 L1 标成 L2。场景包、结果解析与校准只作为接口；本轮没有安装/调用 [Sionna RT](https://github.com/NVlabs/sionna)。

## 算法范围

| 算法 | 当前实现 | 尚未完成 |
|---|---|---|
| 贪心 | 预算下边际收益筛选 | 近似比/最优证书 |
| 精确 Pareto | 最多 14 候选枚举 | 大规模整数规划 |
| NSGA-II | 二进制编码、非支配排序、拥挤距离、种子与参数设置 | 与论文/pymoo 逐例交叉验证 |
| 贪心与鲁棒复核 | 部署后扰动采样/CVaR | 风险进入优化目标/约束 |
| 最强链路/加权分配 | 单时隙接入、带宽与功率基线 | 完整复用/干扰协调 |
| 比例公平 | 当前负载与权重启发式 | 跨时隙历史吞吐 PF |
| UCB | 一次调度内计数探索 | 奖励均值、持续状态与遗憾验证 |
| WMMSE | SISO、固定关联的功率迭代 | 多天线预编码、论文场景复现、统一干扰证明 |

算法出处登记在 `algorithm_catalog.py`。出处链接不代表复现了论文的全部系统、图表和结论。
